## Problem
The dev laptop's agent averaged **~28-30 % of one core**, in bursts every 60 s, and abandoned **~21 WMI calls an hour** at their deadline (1,490 in 69 h). The VM ran at 5 %.

A cdb stack of the hot thread showed it was **COM's host STA** (`combase!CDllHost::STAWorkerLoop`), not a Go thread:
- `wbemdisp!CSWbemEventSource::NextEvent` blocking in COM's modal loop;
- inside it, re-entrant `CSWbemProperty::GetIDsOfNames` → `GetTypeInfo` → activation-context lookups from our WMI queries.

**Cause:** the WMI scripting objects (`WbemScripting.SWbemLocator`, wbemdisp.dll) are registered `ThreadingModel=Apartment`. The agent created and used them from MTA threads, so COM put every one of them in the process's **single host STA** and marshaled every call into it:
- each property read cost two cross-apartment round trips;
- all 5 pooled connections plus the per-namespace connections queued behind that one thread;
- the process trace's `NextEvent` parked the thread for up to 1 s at a time.

This is not a Windows/WMI defect; it is how COM treats apartment-threaded objects called from MTA threads.

## Fix
- **`staThread` (`internal/agent/wmi/sta_thread.go`):** each WMI connection owns one OS thread, initialized as an STA, that runs `connect`, every query and the release.
  - `Query` keeps its ownership rules from #112 (usage count, abandoned call keeps the connection busy, deferred release).
  - `Close` queues the release on the thread instead of waiting under `c.mu`, which would deadlock with a finishing call.
  - A hung call now blocks only its own connection.
- **Anchor STA:** COM registers the hidden `OleMainThreadWndClass` with the first STA and unregisters it when the last one uninitializes. Without a process-lifetime anchor STA, a connection thread starting while another uninitialized failed with *"Cannot find window class"*. The full wmi suite hit it in 2 of 2 runs without the anchor, and passes 3 of 3 with it.
- **Process trace:** the subscription thread initializes as an STA, so `NextEvent` waits on its own thread.
- **Per-namespace connections (executor):**
  - One long-lived connection per non-cimv2 namespace, replaced when unhealthy or due for recycling, with a one-off fallback when busy.
  - This replaces building and tearing down a connection per query (~230 an hour) while a pooled cimv2 connection sat idle.

## Tests
- **`sta_thread_test.go`**, real WMI unless noted:
  - calls on one connection run on one thread, in an STA; two connections use different threads, and neither is the caller's thread;
  - `Close` releases the objects on their thread and stops it;
  - a call abandoned at its deadline keeps the thread busy until it returns, then the release and exit happen;
  - `stop` drains queued work (fake work, no WMI);
  - a panic doesn't kill the thread;
